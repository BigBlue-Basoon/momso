# 채팅 사본 재시도 계약

채팅 DB 변경이 성공한 뒤 사본 쓰기가 실패해도 본래 명령은 성공을 반환한다. `chat-archive-changed` 이벤트는 `{ chatId, state, reason }`이며 `state`는 `saved` 또는 `unavailable`이다. 성공 시 `reason`은 `null`, 실패 시 `archiveMissing`, `notGitRepository`, `permissionDenied`, `pathTooLong`, `diskError`, `redactionFailed`, `credentialStoreUnavailable`, `other` 중 하나다. 여러 방을 한꺼번에 다시 쓰면 `chatId`는 `null`이다. `chat_archive_sync_status`는 `{ state, pendingWrites, pendingDeletions }`를 반환하며, `state`는 `saved` 또는 `pending`이다. 건수는 대기 표식의 수이며 일괄 재시도 하나가 여러 방을 포함할 수 있다.

실패한 쓰기는 앱 DB에 재시도 표식을 남긴다. 삭제는 DB에서 방을 지우는 트랜잭션 안에 삭제 기록과 별도 재시도 표식을 함께 남긴다. 채팅 사본에는 삭제 기록을 쓰며, 기록 쓰기가 실패하거나 앱이 꺼져도 다음 전체 사본 저장에서 다시 시도한다. 이전 버전에서 이미 삭제했지만 사본 처리가 남은 방도 DB 변경 88에서 삭제 기록으로 보존한다. 수동 보관함 저장, 원격 전송 직전과 앱 종료 때 다시 시도한다. 사본의 비밀값 검사는 실패해도 생략하지 않는다.

마지막으로 정상 저장한 채팅 사본의 해시를 DB에 남긴다. 삭제 표식을 쓸 때 기존 사본이 그 해시와 다르거나 확인된 해시가 없으면, 다른 PC의 새 말일 수 있으므로 사본을 보존하고 `chat_deletion_conflict`로 멈춘다. 이전 버전에서 삭제가 중단되어 확인된 해시가 없는 사본도 자동으로 덮어쓰지 않는다. 사본을 쓰는 중 같은 앱의 Git 수신이나 채팅 삭제가 끼어들지 않도록 잠금을 쓴다. 앱 밖의 다른 프로세스가 파일을 직접 바꾸는 경우는 잠글 수 없다.

2026-11-16 개발 앱에서 보고된 `unavailable`은 DB 가져오기 성공 뒤 사본 실패가 명령 전체 실패로 전파되는 코드 경로로 설명된다. 당시 실제 사본 쓰기가 실패한 더 구체적인 원인은 아직 확인하지 못했다. 현재 확인한 개발 DB에는 해당 대화가 남아 있지 않았고, 사본 쓰기는 경로·자격 증명·파일 오류를 같은 `unavailable`로 반환한다. 시험에서는 테스트 자격 증명 공급자를 사용한다.

사본을 만들 때 Git 저장소는 필요하지 않다. Git 상태 확인이 필요한 것은 Git 저장 단계다. 보관 중인 자격 증명을 읽지 못하면 사본을 쓰지 않는다. 비밀값이 포함된 원문을 가리지 못한 채 백업하지 않기 위해서다.

환경 변수 `MOMSO_SAFE_DIAGNOSTICS=1`일 때만 앱 로그에 `momso-safe-event` 한 줄을 기록한다. 단계와 위에서 정한 까닭, 고정된 상대 경로 `chats`와 그 길이 5만 포함한다. 채팅 내용·자격 증명·절대 경로·원래 오류 문자열은 기록하지 않는다. 진단 기록이 꺼져 있어도 이벤트의 `reason`은 제공한다.
