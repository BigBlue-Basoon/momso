name: object-store-connect
title: 원자료 저장소 연결
description: 원자료를 보관할 곳을 몸소에 연결합니다.
---
사용자가 원자료 저장소 연결을 부탁하면 어느 회사의 계정인지 묻는다. 원자료 저장소는 녹음이나 첨부파일 같은 바뀌지 않는 원래 자료를 보관하는 공간이라고 처음에 짧게 설명한다. Google Cloud는 비밀이 아닌 프로젝트 ID를 물어 `momso_object_store_gcp_connect`에 `account`로 넣는다. AWS는 비밀이 아닌 12자리 계정 ID와 지역을 묻고, 로그인 정보가 일정 시간이 지나면 만료되는 임시 정보인지 확인한다. `momso_object_store_aws_connect`에 `account`, `region`, `credentialType`을 넣는다. 임시 정보는 `temporary`, 그 밖은 `permanent`다. 확실하지 않으면 임의로 고르지 않는다. AWS us-east-1은 기존 저장소를 보호하기 위해 설정 화면에서 직접 연결하도록 안내한다. NCP도 설정 화면에서 직접 연결하도록 안내한다. 몸소 사용자 이름으로 `momso-사용자이름`을 만들며, 다른 이름을 임의로 고르지 않는다.

Cloudflare R2는 `momso_object_store_r2_connect`를 인자 없이 호출한다. 브라우저가 열리면 선생님이 Cloudflare에 직접 로그인하고 요청된 권한을 확인하도록 안내한다. 계정 ID와 키는 묻지 않는다. 몸소가 정확한 저장 공간 이름과 비용 가능성을 승인 카드에 표시하면 한 번 허용을 기다린다. 같은 계정의 정확한 이름이 확인된 기존 저장 공간은 새 PC에서 다시 연결할 수 있다. 이름이나 계정이 확인되지 않거나 정보가 달라지면 멈춘다. 거절하거나 중단하면 실행하지 않는다. 여러 계정이 연결되어 있거나 로그인·권한 확인에 실패하면 성공했다고 말하지 않는다. 설정에서 직접 키를 넣는 기존 경로는 남아 있다. 다른 회사의 기존 연결은 몸소의 보안 입력을 사용한다. 키나 비밀번호, 인증 코드를 채팅에 적으라고 하지 않고 도구 인자에 넣지 않는다. 버킷은 원자료를 담을 저장 공간이라고 처음에 짧게 설명한다. 엔드포인트를 물어야 한다면 저장소에 연결하는 주소라고 짧게 설명한다. 승인되지 않은 셸 명령이나 다른 서비스를 사용해 돌아가지 않는다. 도구가 없거나 사용할 수 없으면 연결되었다고 말하지 않는다.

결과가 `bucket_create_unknown`이면 생성됐는지 확인되지 않은 상태다. `created_not_connected`이면 생성은 확인됐으나 연결은 끝나지 않은 상태다. 어느 쪽도 성공으로 말하거나 자동으로 다시 생성하지 않는다. 선생님에게 중단 상태를 알리고 정확한 저장 공간의 상태를 확인할 수 있도록 넘긴다. `bucket_name_taken`이나 `bucket_exists`도 기존 공간을 사용하거나 지우지 않는다.
