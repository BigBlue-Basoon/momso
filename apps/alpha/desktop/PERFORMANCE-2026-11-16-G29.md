# G29 대량 자료 측정

통합 후 주의: 받은 채팅 사본을 DB에 반영하고 대조하기 전에는 덮어쓰지 않도록 일괄 사본 쓰기를 방마다 확인하는 경로로 유지했다. 아래 일괄 쓰기 측정은 통합 전 브랜치의 결과이며 통합 후에는 다시 측정하지 않았다. 복원 시간도 통합 후 재측정하지 않았다.

G28과 같은 PC의 디버그 정보 없는 미최적화 시험 빌드, 임시 폴더의 가짜 자료만 사용했다. 500개 방, 말 100,800개(방 하나는 1,000개, 나머지는 200개), 문서 1,000개, 원자료 번호 2,000개, 용어 1,000개다. 다른 프로그램이 동시에 돌아 시간은 달라질 수 있다. 재현은 `scale_benchmark::synthetic_year_capacity` 무시된 시험을 명시적으로 실행한다. 종료 시 임시 폴더는 시험이 정리한다.

## 구간별 관찰

- G28 채팅 한 건의 Git 저장은 56,808ms였다. 이번에는 50,073ms였으며 2초 목표를 달성하지 못했다.
- 이번 별도 구간 측정에서 사본 500개 재생성 35,962ms, 전체 사본의 비밀값·내용 검증 22,657ms, Git 변경 확인 82ms였다. 독립 실행한 구간들이므로 이 수치를 더한 값이 위 저장 시간과 정확히 같을 필요는 없다. 저장 직전 앱이 실패한 사본 쓰기를 복구하고 가림을 검증하는 전수 경로는 아직 남아 있다. DB 연결과 자격 증명 조회는 한 번씩 재사용하도록 바꿨다.
- 별도의 최종 구간 시험에서 200개 말이 든 사본 한 건 다시 쓰기는 61ms, Git 색인에 한 건을 올리기는 159ms, 한 건 커밋은 232ms였다.
- 문서 한 건의 저장은 개선 후 1,038ms. 개선 전 저장 전체 시간은 별도로 측정하지 못했다. 이전 경로에서 사용하던 전체 문서 검사는 이번 단독 측정에서 962ms였다. 이제 한 건 저장은 그 문서의 규칙만 검사하며, 전체 저장의 전수 검사는 유지한다.
- 채팅 500개 복원은 G28 62,474ms에서 중간 개선 후 34,319ms, SQL 준비 재사용 후 27,245ms와 최종 29,596ms. 각 방마다 연결과 트랜잭션을 다시 만들지 않고 전체를 하나의 트랜잭션에 넣었다.
- 준비 시간의 이번 기존 경로 측정은 4,689ms이며 데이터베이스 준비 1,079ms, 몸소 폴더 준비 3,610ms다. Git 이력이 이미 있는 경우 별도 시험은 10,455ms였고, 최종 변경 후 기본 스킬이 이력에 들어간 상태에서는 3,453ms였다. 두 이력 시험은 기본 스킬이 이미 저장됐는지의 조건이 달라 직접적인 전후 비교는 아니다. 이것은 GUI가 보이기까지의 시간이 아니다. 아직 자료 증가에 따른 시작 시간 변화를 분리해 입증하지 못했다. 이미 최신인 규칙 파일을 열 때 불필요한 Git 검사부터 하던 순서와, 변경 없는 내장 스킬을 반복 검사하던 부분을 고쳤다.
- 방 5,000개, 말 1,000,800개에서 채팅 검색은 결과 있음 2,237ms, 결과 없음 4,865ms였다. 검색 코드는 바꾸지 않았다.

복원 진행 이벤트와 화면 동작은 `RESTORE-PROGRESS.md`에 적었다. G28과 마찬가지로 실제 사용자 자료나 계정은 쓰지 않았다.
