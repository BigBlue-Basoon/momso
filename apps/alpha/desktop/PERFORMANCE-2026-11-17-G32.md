# G32 저장과 검색 작업 기록

기준은 같은 Windows PC, 디버그 정보 없는 미최적화 빌드, 임시 폴더의 가짜 자료다. 50개 방은 말 10,800개, 500개 방은 말 100,800개이며 둘 다 문서 1,000개다. 각 구간은 별도로 잰 값이므로 정확히 더해지지는 않는다.

| 구간 | 50개 방 | 500개 방 |
|---|---:|---:|
| 모든 사본 다시 만들기 | 3,147ms | 35,962ms |
| 모든 사본 가림·내용 검증 | 2,382ms | 22,657ms |
| Git 변경 확인 | 75ms | 82ms |
| 한 방이 바뀐 뒤 저장 전체 | 6,950ms | 50,073ms |

기존 500개 별도 시험의 한 사본 쓰기는 61ms, Git 색인 올리기 159ms, 커밋 232ms였다. 두 전수 작업이 방 수에 따라 늘어나는 주된 구간이다.

통합 전 새 경로 측정: 50개 방은 675ms, 500개 방은 718ms였다. 500개에서는 변경 방 확인 8ms, 가리기 35ms, 사본 쓰기 11ms, Git 색인 71ms, 커밋 242ms였다. 구간은 별도 계측이므로 합이 전체와 같지는 않다. 500개 방 최초 전수 검증은 50,297ms다. 시험에서는 실제 자격 증명 대신 가짜 저장소를 사용했다.

통합 후 최종 측정: 50개 방의 변경 방 확인 5ms, 사본 병합·가리기 101ms, Git 색인 110ms, 커밋 242ms, 저장 전체 940ms. 500개 방은 각각 6ms, 104ms, 76ms, 233ms, 전체 850ms였다. 500개 방에서 추적 기준을 처음 세우는 전수 검증은 85,290ms였으며, 기준 변경 시 다시 필요하다. 같은 조건에서 문서 하나 저장은 1,041ms였다. 모든 값은 이 PC의 한 번씩 잰 값이며 실제 Windows 자격 증명 관리자 접근 시간은 포함하지 않는다.

DB 트랜잭션에 변경 방의 번호와 세대를 함께 남기고, Git에 들어갈 사본만 처리한다. 가리기 기준이 바뀌거나 표식이 없으면 전체를 다시 검증한다. 통합 브랜치의 영구 삭제 기록과 사본 병합 규칙도 지킨다. 세 글자 이상 검색은 삼중 글자 색인으로 후보를 고른 뒤 원래의 정확한 부분 문자열 검사로 확인하고, 짧은 검색은 기존 방식을 쓴다.

5,000개 방의 첫 색인 측정에서는 흔한 말 2,895ms, 없는 말 12ms였다(기존 2,237ms와 4,865ms). 흔한 말이 느려져서 색인의 단어별 빈도를 확인하고 후보가 많은 검색은 기존 방식으로 보내도록 조정했다. 다시 잰 결과는 흔한 말 2,699ms, 없는 말 114ms다. 흔한 말은 이전보다 462ms 느렸고 없는 말은 4,751ms 빨랐다. 색인은 기존 자료를 처음 여는 때 한 번 만들어야 하므로 그때의 작업량과 디스크 사용이 늘어난다.

재측정은 격리된 임시 자료로 기본 시험에서 제외된 `scale_benchmark::synthetic_year_capacity`를 `--ignored --nocapture --test-threads=1`로 실행한다. 저장은 환경 변수 `MOMSO_SCALE_SAVE_ONLY=1`, `MOMSO_SCALE_NO_LARGE=1`, `MOMSO_SCALE_PROFILE=1`, `MOMSO_SCALE_ROOMS=50` 또는 `500`을 쓰고, 5,000개 검색은 `MOMSO_SCALE_SEARCH_ONLY=1`, `MOMSO_SCALE_ROOMS=500`을 쓴다. 실제 앱의 데이터와 자격 증명은 쓰지 않는다.
