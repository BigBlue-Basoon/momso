# momso server의 몸소 폴더 공통 코드 — S29

기준 통합 커밋 `7892dd2af`. 담당: 공통 자료 코드. 서버 HTTP·MCP와 화면은 이 작업에서 바꾸지 않는다. `apps/alpha/desktop/src-tauri/momso-core`는 Tauri에 기대지 않는 별도 Cargo 패키지이며, 데스크톱과 같은 원본의 문서·스킬 형식과 용어 사전·스킬 저장 로직을 사용한다. 이 글의 서버 API는 연결을 위한 Rust 계약이며 현재 서버에 연결된 엔드포인트가 아니다.

## 서버가 끼울 자리

1. 인증된 사용자의 VM 전용 경로를 서버 설정에서 정하고 부모 폴더를 준비한 뒤 `filesystem::initialize(&root)`를 호출한다. 사용자나 AI가 임의의 서버 절대 경로를 고르게 하지 않는다. 오류는 저장하지 못했음을 반환한다. 초기화는 기본 스킬의 원본과 제공자별 사본 및 상태를 만든다.
2. S23 도구는 이름을 검증하는 `filesystem::read_callable_skill(&root, name)`과 `dictionary::list(&root)`를 통해 스킬·사전을 읽는다. 스킬이 꺼졌거나 사본이 충돌하면 오류를 반환한다. 사이트 조작 가능 여부, 사람 확인 및 쓰기 승인은 S23/S20 정책을 통과해야 하며 문서·웹 내용은 AI의 지시가 아닌 자료로 취급한다. 사람 이름을 AI가 확인됨으로 저장하지 않도록 서버 어댑터에서 구분한다.
3. 파일 형태의 문서 생성·읽기·수정은 `filesystem` 함수를 사용한다. 수정에는 `document::content_hash`가 만든 이전 값이 필요하며 달라졌으면 `conflict`다. 파일에는 원문과 호환되는 YAML 머리말이 들어간다. 서버의 문서 목록 색인과 쓰기 승인 연결은 별도 작업이다.
4. 스킬 편집은 `skill_storage`의 함수와 기존 변경 확인값을 사용한다. 사용자가 고친 스킬을 초기화가 덮지 않는다. 사전 수정은 `dictionary` 함수와 목록의 변경 확인값을 쓴다.
5. `git::save`는 지정된 `zettels`, `dictionary`, `skills` 파일만 로컬 이력에 담는다. 네트워크 업로드 기능은 없다. 서버가 이력에 담을 파일을 정하고 사용자 승인·기존 변경 확인을 담당한다.

## 경계와 검증

일반 쓰기 잠금은 한 서버 프로세스 안에서 공유된다. 기본 사전 판올림은 Linux 파일 잠금도 사용한다. 같은 폴더에 별도의 서버나 잠금을 따르지 않는 다른 프로그램이 동시에 쓰는 경우와 심볼릭 링크 교체 경합은 아직 해결하지 않았다. 그러므로 서버는 한 몸소 폴더의 단일 작성자로 실행해야 한다. 문서 파일과 DB 색인 갱신을 하나의 복구 가능한 거래로 묶는 일도 남았다. Linux의 Git 명령은 셸을 거치지 않고 `git` 실행 파일을 PATH에서 찾는다. 줄 끝은 기존 문서 머리말의 CRLF를 보존하며 새 파일은 LF를 쓴다.

**이식 규모:** 크게 옮긴 파일은 문서 머리말·폴더 처리 부분의 `archive_zet.rs`, 스킬 형식 부분의 `skills.rs`다. `yoga_dictionary.rs`에는 Linux 기본 사전 판올림을 더했다. `skills_write.rs`에는 공통 패키지용 경계와 Linux의 Git 환경 값을 더하고, 첫 Git 저장 전 기록되지 않은 스킬 사본을 끌 때 실패하던 경우를 고쳤다. Windows 빌드 차례는 기다리지 않으며, 통합 담당이 Windows에서 이 파일들과 관련 기존 시험을 확인한다.
