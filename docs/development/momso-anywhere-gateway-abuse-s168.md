# 입구 요청과 비용 (S168)

확인일: 2026-11-25. 코드와 가짜 시험을 기준으로 작성했다. 실제 고객 설치에 이 변경을 배포하거나 부하 시험하지 않았다. 상태별 고객 비용과 그 가정은 [S161](momso-anywhere-customer-cost-s161.md)을 보라.

## 세션 없는 요청

| 경로 | 세션 없는 처리 | VM·Google API·기록 |
| --- | --- | --- |
| `GET/HEAD /__momso/ready` | 고정 JSON | VM·Google API 없음 |
| `GET/HEAD` 공개 manifest와 다섯 아이콘 | 이미지 안 파일 응답 | VM·Google API 없음 |
| `GET /__momso/auth/return`, `/__momso/login.mjs` | 정적 로그인 복귀 코드 | VM·Google API 없음 |
| `GET /__momso/auth/challenge` 및 로그인 전 문서 탐색 | 서명된 5분 challenge·로그인 이동 | VM·Google API 없음. 세션 키 파일 읽기 |
| `POST /__momso/auth/finish` | 유효한 같은 출처 challenge를 검사한 뒤 Google 서명·nonce·소유자 sub 검사 | Google 인증 공개키 조회가 있을 수 있음. 소유자가 아니면 세션 미발급, VM 접근·깨우기 없음 |
| `/__momso/proxy-health` | 별도 비밀 proof 없으면 403. proof가 맞을 때만 사설 `/health` 조회 | 세션 없는 proof 검사는 VM을 깨우지 않음. `/health`는 활동 시간에 포함되지 않음 |
| `/__momso/pause/confirm`, `/__momso/pause/release` | 설정된 로그인 출처와 일회용 표 필요 | 표 확인은 VM에서 처리하지만 VM을 깨우지 않음. 표 내용은 URL이 아니라 본문에 둠 |
| 나머지 API와 쉬기 준비·상태 | 로그인 없는 fetch는 401, 문서 탐색은 로그인으로 이동 | VM·Google API 없음 |

잘못된 Host·출처 등은 입구가 거절한다. 입구 Python의 `log_message`는 아무것도 남기지 않지만 Cloud Run 앞단 요청 로그·감사 로그 및 Google 측 로그는 별개다. 요청 건수와 저장량 제한을 이 코드가 보장하지 않는다. 세션은 30일이며 `POST /__momso/auth/logout`은 브라우저 쿠키를 지운다. 서버에 별도의 세션 폐기 목록은 없으므로 탈취된 쿠키가 자동으로 즉시 폐기되는 것은 아니다. 소유자 세션은 서명·시각·소유자 sub를 검증한다.

인증된 요청만 일반 VM 경로에 도달한다. 서버의 `maintenance::admit`은 유효한 사설 토큰을 가진 실제 쓰기와 지정된 조회만 `lastActivityAt`에 반영한다. `/health`와 무인 상태 확인은 해당 목록이 아니다. 입구의 HMAC 점검은 `/health`에만 연결되고 실패해도 깨우지 않는다. 소유자 요청이 VM에 닿지 못하면 5초 동안 같은 인스턴스 안에서 깨우기 요청을 합치며, wake 코드는 VM이 이미 시작 중이면 다시 start하지 않는다. 여러 Cloud Run 인스턴스 사이에 공유되는 잠금은 아니다.

## 설정과 한계

PC 새 설치·올리기와 VM 업데이트 어댑터는 `gcloud run deploy --max=1`, 휴대폰 REST 설치·전환은 서비스 `scaling.maxInstanceCount=1`을 쓴다. 이미 설치된 곳도 이 코드로 입구를 다음에 배포할 때 적용된다. 기존 동시 요청 80, 요청 제한 3,600초, 1 vCPU·512 MiB를 바꾸지 않았다. SSE와 업로드를 위해 시간 제한을 줄이지 않았다. 한 인스턴스가 80개 요청으로 차면 정상 사용자가 대기하거나 실패할 수 있다. 기존 인스턴스보다 엄격한 제한은 서비스 가능성과 맞바꾸는 것이다.

**최대 1개는 청구서의 절대 상한이 아니다.** Google은 트래픽 급증 등에서 설정을 잠시 초과할 수 있다고 명시한다. 요청 건수·응답 바이트·로그 저장·다른 Google 서비스 사용량에도 별도 비용이 난다. 로그인 공개 경로를 대량 호출해도 Cloud Run 처리량·전송비가 늘 수 있고, 만료되지 않은 탈취 세션은 소유자와 구별할 수 없다. [Google 최대 인스턴스](https://docs.cloud.google.com/run/docs/configuring/max-instances), [서비스별 설정](https://docs.cloud.google.com/run/docs/reference/rest/v2/projects.locations.services).

## 비용 비교 예시

서울 요청 기반 단가와 무료 금액은 [공식 Cloud Run 요금](https://cloud.google.com/run/pricing) 및 위 S79의 서울 선택 기록을 따른다: vCPU초 $0.0000336, GiB초 $0.0000035, 요청 100만 건 $0.40. 무료 할인은 결제 계정 전체에서 공유하며 Iowa 기준 월 180,000 vCPU초·360,000 GiB초에 해당하는 금액, 요청 200만 건이다. 다른 프로젝트가 이미 썼다면 없다.

30일 내내 각 인스턴스에 요청이 있어 활성으로 청구되고, 1 vCPU·0.5 GiB이며 시작·종료 초과, 무료 할인, 요청·전송·로그·VM·세금을 제외한 비교: 1개 × 2,592,000초 × (0.0000336 + 0.5 × 0.0000035) = **$91.63**. 제한 전 예시로 100개가 동시에 같은 조건이면 **$9,162.72**. 100은 공식 문서의 기존 판 단위 기본값을 쓴 비교 가정이며, 당시 실제 최대·실제 사용량이나 보장되는 최악값이 아니다. 요청 1억 건이 추가되면 무료 한도 전 $40가 더 들고 전송·로그는 별도다. 무료 한도를 이 입구만 쓴다면 CPU·메모리의 Iowa 기준 할인 합계 최대 $5.22가 위 계산에서 빠질 수 있다. 요청량과 전송량에 상한이 없으므로 제한 전후 모두 **실제 최악 월 총액은 이 설정만으로 산출할 수 없다**.

## 검증 경계

가짜 시험은 익명 요청, 타인 로그인, 세션·깨우기 합치기, 서비스 설정과 스트림 전달을 확인한다. 실제 입구 Dockerfile로 만든 로컬 컨테이너에 익명 요청 200회를 보냈을 때 시험용 깨우기 호출은 0회였다. 고객 Google Cloud에는 배포하지 않았다. 실제 기기에서 장시간 SSE·대용량 업로드 및 다수 동시 요청은 확인 전이다.
