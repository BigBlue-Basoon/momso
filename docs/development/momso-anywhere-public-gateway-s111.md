# Public gateway image and publisher costs (S111)

Checked 2026-11-24. No cloud resources, package visibility or billing settings were changed by this work.

## Registry choice

Google's current [Cloud Run deployment documentation](https://docs.cloud.google.com/run/docs/deploying#supported-container-registries-and-images) explicitly supports **public GHCR images directly**. The earlier assumption that every GHCR image requires a customer Artifact Registry remote repository is incorrect. Use `ghcr.io/<owner>/momso-gateway@sha256:<digest>` directly in the signed release manifest. The signed manifest authenticates the entire image reference including its digest; never replace it with a tag or alter it after verification. Existing PC installer, browser provider and VM updater submit that exact reference to Cloud Run, staging a revision and retaining the old revision for rollback. Existing customer gateways are upgraded by the normal signed upgrade path; their URL is preserved. Actual GHCR-to-Cloud-Run deployment and rollback remain unverified until HQ runs them.

Public [GitHub Packages](https://docs.github.com/en/billing/concepts/product-billing/github-packages) usage is free; GitHub currently says Container Registry storage and bandwidth are free, with at least a month's notice before a policy change. This is not an eternal guarantee, and GitHub terms/rate limits still apply. No publisher Google registry is involved in the image pull. Google's [remote repository documentation](https://docs.cloud.google.com/artifact-registry/docs/repositories/remote-overview) confirms GHCR can alternatively be a custom HTTPS Docker upstream. It adds customer cost and configuration, so is not provisioned by default. If used, the first 0.5 GiB-month of [Artifact Registry storage](https://cloud.google.com/artifact-registry/pricing) is free across the entire billing account, not per project; cached images above it, scanning and some transfers can cost money. Same-region Google transfers are free under the documented conditions. The image's actual size and billing-account usage have not been measured; free-tier eligibility cannot be promised.

## Publishing and migration

1. In the public repository, review the exact source and web assets first. The manually dispatched `.github/workflows/anywhere-gateway-ghcr.yml` builds the network web assets and gateway, then publishes an image tagged with the source commit and reports the digest. It does not run automatically. Confirm that the selected commit has the intended current screen and that the image contains no secrets. Standard GitHub-hosted runners in public repositories are [free](https://docs.github.com/en/billing/concepts/product-billing/github-actions), subject to limits. The package must explicitly be made public in GitHub package settings; publishing alone does not prove visibility. Validate anonymous pull and exact digest before continuing.
2. The signing-key owner signs a new monotonic release manifest containing the exact public GHCR reference and digest. Use the existing S76 signing procedure; do not expose or copy the private key. Release bundles and the image must correspond to the reviewed build.
3. Run the existing signed installer or automatic updater against a **test** installation, check health and rollback, and then upgrade the intended installation. For the browser's existing-entry discovery, retain each verified old image reference and digest in the start-site `trustedGatewayImages` configuration throughout the transition; an old gateway otherwise will not be found. Protect this configuration and remove obsolete entries only after the corresponding installations have moved. No customer project or actual package was modified by this change. A GHCR outage, private package, missing digest, or Cloud Run import failure must not be represented as a successful upgrade.
4. Only after all installations no longer need the old private publisher image and rollback implications have been reviewed, HQ can remove each exact temporary reader binding. First describe the repository IAM policy and verify exact member, role, condition, repository region and project. Then, for each confirmed *unconditional* binding, use:

   `gcloud artifacts repositories remove-iam-policy-binding momso-gateway --project=PROJECT --location=REGION --account=AUTHORIZED_ACCOUNT --member=EXACT_MEMBER --role=roles/artifactregistry.reader`

   Conditional bindings need their exact condition specified; do not remove a broader or shared binding. Preserve publisher access needed for other work. The previous Cloud Run revision may still refer to the old image; verify rollback before revoking access.

## Publisher cost exposure

The named publisher project's actual inventory and billing-account totals were **not verified**: the supplied account was denied Cloud Run list permission. The following is a risk inventory, not a claim that every resource exists or costs money. HQ should inspect billing exports, Cloud Run, Artifact Registry, Cloud Storage, logging and network resources for that specific project and its shared billing account.

| Possible source | When charges can arise | No-publisher-GCP-cost alternative / qualification |
|---|---|---|
| Public common login/start Cloud Run | Requests, CPU, memory, minimum instances and outbound network can exceed [Cloud Run free usage](https://cloud.google.com/run/pricing); allowance is shared by billing account and regional pricing applies. Static files can incur egress even when request compute is free. | Host only static login/start files on a third-party free static host; [Cloudflare Pages](https://developers.cloudflare.com/pages/functions/pricing/) says static asset requests are free and unlimited, subject to its terms and limits. DNS/domain and any functions remain separate. Re-register OAuth origins and redirects; do not migrate without review. |
| Existing publisher Artifact Registry | Image storage, downloads and scanning can exceed the [0.5 GiB-month allowance](https://cloud.google.com/artifact-registry/pricing), shared across projects on the billing account. Public access can create unbounded request-driven transfer. | Public GHCR as above; remove old repository only after migration and rollback review, not as part of this change. |
| Publisher Cloud Storage / release assets if present | Storage, operations and egress can incur charges; [Cloud Storage pricing](https://cloud.google.com/storage/pricing) depends on region and access. | Reviewed public GitHub release assets or another appropriate free static host; check that provider's terms and limits. |
| Cloud Logging / monitoring if enabled | Request volume can increase ingestion or retention beyond [Logging pricing](https://cloud.google.com/stackdriver/pricing); monitoring and network services may add charges. | Reduce collection/retention only after security review, or remove the GCP-hosted service; a free limit is not a hard spending cap. |
| Publisher Secret Manager, build, network and any other live resources | Versions/accesses, build minutes, egress and other provisioned services may be billable even with few users; [Secret Manager](https://cloud.google.com/secret-manager/pricing) free limits are shared across the billing account. | Inventory actual resources and disable only with explicit approval. Public GitHub Actions standard runners avoid publisher Cloud Build for this image. |

No free-tier estimate guarantees a zero bill. In particular, budgets are notifications rather than automatic hard limits; a verified zero-GCP-cost design requires removing or relocating the billable publisher services, not merely configuring a budget. No live resource was removed here.
# S131: Cloud Run 이미지 지문

Cloud Run은 GHCR의 OCI index를 가져올 때 linux/amd64 manifest 지문으로 기록할 수 있다. 서명 목록에는 index가 아닌 단일 linux/amd64 manifest 지문을 넣는다. GHCR workflow는 provenance와 sbom을 끄고 레지스트리의 mediaType을 확인한 뒤 서명에 쓸 주소를 출력한다. S141 이후 `momso_release_sign.py sign --verify-gateway-registry ...`, 운영 서명과 workflow는 같은 GHCR 익명 HTTP 검사를 쓰므로 Docker 없이 공개 여부·manifest 종류·응답 지문을 확인한다. 이전 방식은 Docker buildx가 필요했다. 진짜 릴리스 발행은 별도다.
