# S147 쉬기와 복원 연습: 준비 중

## 확인한 현재 경로

- 암호화 백업 복원 함수는 `scripts/momso_anywhere_backup.py`의 `restore`와 `_restore_v3`에 있다. `scripts/momso_anywhere_backup_agent.py`의 `restore` 명령이 이를 호출하며 충돌을 결과로 돌려준다.
- 같은 설치 ID로 VM을 다시 만들 때 위 명령을 서버 시작 전에 호출하는 길은 현재 PC 설치기 `scripts/momso_server_install.py`와 `scripts/momso_anywhere_vm_services.py`의 설치 순서에서 확인하지 못했다. 설치 중 서버와 백업 작업자가 시작되므로, 복원 전에 빈 자료가 백업되는 상황을 막는 작업도 필요하다. 기존 설치 상태에서 `anywhere`를 다시 부르는 것만으로 백업 복원이 된다고 판정하지 않는다.
- 금고의 비밀을 새 VM에서 읽는 데 필요한 `scripts/momso_anywhere_vault_identity.py`의 `rewrap_for_host`는 복원 에이전트에서 쓰일 수 있다. 새 VM의 설치·서버 시작과 함께 검증된 경로는 아직 없다. 파일이나 보관된 열쇠를 덮어쓰지 않는 확인이 필요하다.

## 이번에 만든 조각

`scripts/momso_anywhere_rehearsal_s147.py`의 단계 처리기는 가짜 공급자에서 설치, 표식 지문, 쉬기, 백업 보존 확인, 같은 ID 복원, 지문 대조, 정리와 잔여 자원 확인을 순서대로 시험한다. 충돌하는 보호 ID는 어떤 공급자도 부르기 전에 거절한다. 실패 후에는 소유권을 확인하고 설치를 시도한 시험 자원만 정리한다. 항목 전부를 확인했다고 증명하지 않은 잔여 자원은 0으로 치지 않는다.

실제 Google 연결은 아직 없다. 명령은 요청된 인자를 받아도 `restore_not_integrated`와 JSON 결과를 내고 종료하며, VM이나 다른 자원을 만들지 않는다. 가짜 공급자 시험은 실제 설치·복원을 입증하지 않는다.

## 남은 일

1. 같은 설치 ID와 소유권을 확인해 보존된 버킷·암호화 키·금고 열쇠를 재사용하고, 서버 및 새 백업 작업자 시작 **전**에 복원하는 경로를 만든다. 실패나 충돌은 서버와 백업을 시작하지 않고 남긴다.
2. 이 경로를 PC 설치기의 재설치에 연결한다. 기존 금고와 다른 자료는 덮어쓰지 않으며, 끊긴 뒤 재시도와 빈 설치의 구분을 시험한다.
3. S117a의 기존 설치·보호 ID 검사·IAP SSH·쉬기·전부 지우기·잔여 자원 조회를 실제 S147 어댑터에 연결한다. 표식은 시험용 VM 안에만 넣고 지문만 기록한다.
4. 가짜 Google으로 실제 어댑터를 통과하는 전체 시험을 마친 뒤 실제 실행을 연다. 그 전에는 `hq/s147-done`을 만들지 않는다.
