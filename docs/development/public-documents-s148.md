# 공개 스냅샷 문서 링크 보완

기준 스냅샷 `c619e211d40a815aa8d6de7d027552dc14dc4d9d`의 Markdown에서 누락된 상대 링크 34곳을 확인했다. 공개 스냅샷에 없던 대상과 그 문서의 연쇄 참조를 따라 [추가할 문서 목록](../../scripts/public-documents-s148.txt)에 30개를 적었다. 그중 한 문서는 작업 중 갱신된 화면 인계 문서에서 새로 참조한다. 서버 계약 문서 한 장에는 개발 VM의 개인 작업 경로가 있어 제외하고, 세 문서에서 그 링크를 일반 글로 고쳤다. 다음 스냅샷을 만드는 담당자는 목록의 파일을 통합 저장소에서 가져오고, 이 안내·검사 스크립트·시험·의존성 목록과 변경된 워크플로 및 화면 인계 문서도 함께 담는다. 이 작업은 스냅샷 저장소를 직접 수정하지 않았다.

30개를 넣고 참조를 고친 시험 사본 전체를 공개 위생 검사와 이 PC의 별도 비공개 이름 목록으로 검사해 발견 0건이었고, 상대 링크 검사도 0건이었다. 개발자 홈 디렉터리를 가리키는 경로도 별도로 확인했다. 알려지지 않은 이름이나 별도로 분류해야 할 문맥까지 자동으로 판별한다는 뜻은 아니므로 공개 전 검토는 유지한다. 외부 주소, 같은 문서의 제목 조각, 코드 블록의 예시는 파일 존재 검사 대상이 아니다.

깨끗한 공개 사본에서 `python -m pip install -r scripts/requirements-public-docs.txt`를 실행한 뒤 `python -m unittest discover -s scripts -p test_public_markdown_links.py`와 `python scripts/check-public-markdown-links.py`를 실행한다. 상대 링크와 이미지, 참조 링크, HTML 링크의 대상은 대소문자까지 검사한다. 공개 저장소의 별도 가벼운 문서 CI에도 같은 검사를 넣어 문서 변경 때 Windows 설치 파일을 다시 빌드하지 않는다. 사설 저장소의 전체 문서는 공개 스냅샷과 구성이 달라 이 공개 전용 검사를 적용하지 않는다.
