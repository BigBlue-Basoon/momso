# 바디코디 공개 메뉴를 본뜬 연습 시험 (S166)

2026-11-25, 개발 Linux VM에서 임시 서버·가짜 회원·가짜 계정과 실제 헤드리스 Chrome으로 시험했다. 진짜 바디코디 화면·계정에는 접속하지 않았다. 연습 사이트는 테스트 코드 안에만 있으며 실제 화면이나 문구를 복제하지 않는다. 바디코디 공개 메뉴 근거는 `crm-public-sources-s164.md`다.

## 확인한 경로

- `s166_codex_reschedule_waits_for_approval_and_reads_result`: 가짜 Codex CLI와 실제 server·브라우저를 사용한다. 한 채팅에서 저장된 가짜 로그인 둘 중 하나를 선택하고, 두 쪽으로 나뉜 가짜 예약 명단에서 `다음`을 눌러 마지막 쪽을 읽는다. 같은 이름에 다른 가짜 전화번호인 두 사람을 보여 주고 어느 사람인지 되묻는다. 사용자가 후속 메시지에서 둘째 사람과 `11:30` 변경을 명시해 허락하면 같은 채팅에서 시간 입력·확인 창·저장·결과 재조회를 수행한다. 별도 채팅에서 사이트 조작을 거절하면 저장 요청이 늘지 않고, 허용하면 변경 시간이 든 요청이 늘어나는 것도 확인한다.
- `both_provider_server_browser_approval_round_trip`: 가짜 Claude·Gemini 응답을 실제 server 도구 루프와 브라우저에 연결해 변경 내용을 알리고 사이트 승인을 받은 뒤 시간 입력·확인·저장·결과 재조회를 확인한다. 공급자 API 키는 시험용 가짜다.
- `mobile_s47_real_screen_probe`: 별도 시험 화면을 390×844로 열어 사람에게 넘기는 안내, 일회용 코드, 저장된 로그인 선택과 사이트 승인 카드를 확인하고, 승인 뒤 가짜 변경 결과를 읽는다. 화면 기준 스냅샷은 `e803c5c`다.
- `requested_login_survives_reconnect_and_reaches_only_site`: 별도 가짜 로그인 화면에서 저장된 로그인 선택과 비밀값 가림을 확인했다.

## 범위와 주의

동명이인 선택 뒤 같은 채팅에서 이어 가는 것은 정해진 가짜 Codex 대본으로 시험했다. 세 공급자는 진짜 모델이 아니라 정해진 도구 호출을 내는 가짜 공급자다. 휴대폰 화면 시험과 Claude·Gemini 시험의 가짜 사이트는 각각 독립된 시험 사본이다.

현재 브라우저 승인은 채팅방과 사이트 단위다. 이 시험에서는 처음 조작하기 전에 변경 내용이 채팅에 보이고 승인 카드가 나타나지만, 이전에 해당 사이트를 허용했다면 저장할 때마다 새 카드가 나타나는 기술적 보장은 없다. 실제 사용에서 AI는 저장 전 변경 내용을 설명하고 사용자의 답을 받도록 안내해야 한다. 다른 사이트를 제한하거나 임의의 쓰기 판별 규칙을 추가하지 않았다.

전체 서버 시험: `54207dfbf`에서 77 통과, 0 실패, 브라우저 등 환경이 필요한 10개 제외. 위 실제 브라우저·휴대폰 시험은 별도로 실행했다. 같은 채팅 후속 선택을 추가한 뒤에는 해당 시험과 fmt·clippy를 다시 통과했다. 일반 시험 제외 항목 전부를 이번에 돌렸다는 뜻은 아니다.

화면에서 정할 것: 예약 변경·결제·삭제처럼 바깥을 바꾸는 일에 매번 확인을 받을지, 사이트를 한 번 허락하면 맡길지.
