# 공개 소스에서 설치 파일 준비

2026-11-24 개발자의 결정: “인증서는 돈 안낼래.” Windows 코드 서명 인증서는 구매하지 않고 설치 파일의 SmartScreen 경고를 받아들인다. 자동 업데이트용 Tauri 서명은 유지한다.

충실도 대조: 발언은 인증서에 돈을 내지 않겠다는 결정이고, 본부가 같은 지시에서 인증서 서명 없는 설치 파일·SmartScreen 경고 수용·자동 업데이트 서명 유지를 명시했다. 결정 주체와 조건을 바꾸지 않았다.

공개 저장소의 한 커밋을 `git archive`로 추출한 사본에서 의존성 설치와 제품 NSIS 빌드, 비공개 이름 검사, 실제 첫 화면과 제거를 차례로 수행한다. 원래 공개 클론의 수정 파일은 건드리지 않는다. 서명이나 공개는 수행하지 않는다. 아래는 본부가 **공개된 커밋의 전체 SHA**를 정한 뒤 기존 작업 폴더에서 실행할 명령이다.

빌드 스크립트나 데스크톱 CI 워크플로를 바꿀 때는 통합 전에 깨끗한 사본에서 `.github/workflows/desktop-alpha.yml`의 의존성 설치·검사·시험·빌드 명령을 순서대로 실행한다. 운영체제나 설치된 도구 차이로 실행하지 못한 단계는 통과로 쓰지 않고 이유와 실제 환경을 기록한다. 일반 빌드는 7-Zip이나 비공개 목록을 요구하지 않으며, 릴리스 준비 명령이 제품을 임시 설치해 내용을 검사한다.

S125 로컬 CI 재현은 공개 스냅샷 `64589924265d454e7da1fdff93ccdf02f07f04d0`의 바이트를 검증한 사본에 수정 후보 파일을 덧씌워 Windows와 Rust 1.100.0에서 실행했다. 공개 단일 커밋 빌드나 GitHub CI 실행 결과는 아니다. Rust 전체 시험은 894개 통과·78개 무시, clippy는 통과했다. CI의 설치 파일 캐시 삭제 명령은 자동 승인 심사에서 재귀 삭제가 거절되어 실행하지 못했다. 해당 사본의 삭제 대상 경로가 없다는 것은 별도로 읽기 확인했다. GitHub Actions의 캐시 복원은 로컬에서 재현하지 않았고 별도 Cargo 대상 폴더를 사용했다.

같은 후보에서 7-Zip과 비공개 이름 목록 없이 `npm run desktop:build`가 종료 코드 0으로 끝나 NSIS 설치 파일을 새로 만들었다. 이어 `desktop:artifact:metadata`도 로컬 시험임을 나타내는 출처 값으로 통과했다. 산출물은 공개 커밋 하나로 만든 릴리스가 아니므로 서명하거나 배포하지 않는다. 종료 코드를 재확인하려고 시작한 중복 빌드는 원래 npm 실행 기록의 성공을 확인한 뒤 중단했다.

```powershell
python scripts/build-public-desktop-s124.py --commit <공개-main-커밋의-40자리-SHA> --output "$env:LOCALAPPDATA\momso-release-prepared\public-<커밋-짧은-이름>"
```

명령은 공개 클론의 `origin` 주소와 원격 `main` 이력, 버전 `0.1.1`, 업데이터 주소를 확인한다. `git archive`에는 `core.autocrlf=false`를 지정하고 추출된 파일 목록과 바이트를 커밋의 Git blob 전부와 대조한다. Windows 기본 설정으로 추출하면 일부 줄바꿈이 달라질 수 있기 때문이다. 이미 있는 출력 폴더는 덮어쓰지 않는다. Windows 빌드 잠금을 잡고 메모리·디스크 기준을 확인하며, 추출된 파일이 의존성 설치나 빌드 중 바뀌거나 화면·Rust 소스 폴더에 새 파일이 생기면 실패한다. 실제 제품 시험은 기존 사용자 자료를 쓸 수 있으므로 소유자의 승인 아래 실행한다. 성공하면 검사 영수증에 `sourceCommitSha`와 `sourceTreeSha`를 넣는다. 시험 과정에서 사용자의 비공개 목록 파일을 읽되 내용은 출력하지 않는다.

설치 파일은 커밋의 소스 외에 잠금 파일로 지정된 외부 의존성과 Microsoft 빌드 도구, 공개 커밋의 준비 스크립트가 지문을 확인하는 Node 런타임을 포함한다. 이 절차는 소스 출처를 확인하지만 다른 컴퓨터에서 같은 설치 파일 바이트가 재현된다는 뜻은 아니다.

2026-11-24 공개 `main` `3e39afbd5171db1a157054f40bd99c38ae74192a` 연습: Windows의 기본 줄바꿈 변환을 끈 `git archive`는 추적 파일 669개 전부가 커밋 blob과 바이트까지 일치했다. `npm ci`, 화면 빌드, 제품 NSIS 생성은 진행됐다. 그러나 공개판의 마지막 검사기는 설치되지 않은 `7z`를 호출해 `spawn 7z ENOENT`로 실패했다. 별도의 임시 설치 검사에서는 설치된 앱에 빌드 사용자의 폴더 경로가 남아 있어 첫 화면 실행 전에 거절됐다. 연습 설치 파일은 서명·공개하지 않는다. 경로 치환과 개발 전용 경로 제외, 7-Zip 없는 임시 설치 검사는 통합 후보에 반영돼 있으며, 새 공개 스냅샷의 커밋으로 다시 빌드·검사해야 한다.

수정 검증은 위 공개 사본에 빌드 스크립트·검사기·Rust 파일 등 여섯 파일만 바꾼 별도 후보로 진행했다. 이 후보의 제품 NSIS 빌드가 통과했고 사용자 폴더 경로는 앱 실행 파일에서 검출되지 않았다. 임시 설치한 파일과 묶음 원본 3,753개를 검사한 뒤 실제 첫 화면을 확인하고 제거했다. 기존 몸소 보관 폴더의 파일 수정은 없었으며 앱 설정·로컬 자료 메타데이터 66건이 바뀌었다. 이 후보는 공개된 단일 커밋이 아니므로 공개 소스 SHA를 영수증에 넣지 않았고 서명하지 않는다. 공개 스냅샷 병합 후 단일 커밋으로 새 명령을 실행해야 한다.

서명 명령은 새 영수증의 설치 파일 지문·비공개 목록 지문·첫 화면 확인을 검증한 다음, 기록된 커밋이 실제 공개 `main` 이력에 있는지 원격에서 다시 확인한다. 잠금 파일로 설치한 Tauri 서명 도구와 Node는 결과 폴더의 `signer`에 따로 두며 서명 전 그 전체 지문도 확인하므로 빌드 폴더를 지운 뒤에도 사용할 수 있다. 이전 S118 설치 파일의 영수증에는 공개 소스 커밋이 없으므로 서명 전에 거부된다. 기록은 독립적으로 서명된 빌드 증명이 아니며, 출력 폴더와 시험 환경을 신뢰할 수 있도록 보호하고 본부가 공개 커밋과 결과를 검수해야 한다.

공개 `3e39afb`의 잠금 파일로 설치된 Tauri CLI 2.12.4와 묶음 Node를 별도 폴더에 복사해 16개 파일의 비공개 이름 검사를 통과했고, 임시로 만든 가짜 열쇠로 서명까지 확인했다. 실제 서명 열쇠는 사용하지 않았다.

기본 빌드 대상 폴더는 이 작업트리의 `target` 하나이며 `--target`으로 바꿀 수 있다. 성공 후 임시 소스 사본은 지우고 빌드 대상 폴더는 소유자 정리를 위해 경로를 출력한다. 오류 시 재현을 위해 임시 사본이 남을 수 있다. 설치 파일은 결과 폴더에 따로 보존한다. 작업이 끝나기 전 30 GiB 아래로 내려가면 중단한다. 사용자 계정의 기존 몸소 자료는 지우지 않는다.

2026-11-25 빌드 순서 조정: 설치 파일 빌드는 공유 잠금을 최대 75분 사용할 수 있다. 이 준비 스크립트는 잠금을 잡은 뒤 74분에 중단 절차를 시작해 해제 시간을 남긴다. `hq/s126-done` 확인 후 공개 `main`을 다시 가져왔을 때도 `3e39afbd5171db1a157054f40bd99c38ae74192a`였고, 그 커밋에는 7-Zip 검사 호출이 남아 있다. 위에 기록한 연습 실패를 같은 소스로 다시 반복하지 않았다. 7-Zip 제거를 포함한 다음 스냅샷이 공개 `main`에 합쳐진 뒤 본부가 지정한 SHA로 명령을 다시 실행해야 한다.

2026-11-25 공개 `main` `f94a534739cbfe44ea3f7ea8f610a20ef15b7896`에서 다시 실행: 추적 파일과 커밋의 일치 확인, 의존성 설치, NSIS 빌드, 임시 설치한 파일과 묶음 원본 3,753개 검사, 별도 데스크톱 첫 화면, 제거가 통과했다. 설치 파일 SHA-256은 `622fe237d59830c57a5e0c344b6ef3d2bdac09bfe2f230ffb78a3f1141b7a258`이다. 준비 기록에 공개 커밋과 트리 SHA, 비공개 검사 목록의 SHA, 첫 화면 결과가 들어 있다. 현재 사용자로 앱을 실행하면서 기존 몸소 자료 폴더의 파일은 바뀌지 않았고 앱 설정·로컬 자료 메타데이터 67건이 바뀌었다. 열쇠가 없는 경로를 주어 서명 전 검사가 열쇠 입력 직전까지 통과함을 확인했으며 실제 열쇠는 사용하지 않았다. 이는 서명이나 공개 완료를 뜻하지 않는다.

서명 후에는 [릴리스 준비 절차](desktop-release-preparation-s118.md)의 공개키 검증과 릴리스 검수를 수행한다. 원하는 태그는 `v0.1.1`, 업데이트 파일 주소는 `releases/latest/download/latest.json`이다. `anywhere` 릴리스는 `scripts/momso-release-channels.py publish-anywhere`로 만들고, 공개 후 `verify-desktop --tag v0.1.1`로 최신 릴리스를 확인한다.
