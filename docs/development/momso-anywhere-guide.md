# momso anywhere 안내서

이 문서는 휴대폰에서 쓰는 momso의 설치·운영 경로를 모은 안내서다. 개별 작업 문서는 당시의 결정과 시험 기록으로 보존하며, 현재 구현 여부와 실제 확인 여부를 구분한다. 운영 계정이나 고객 자료에 대한 시험을 뜻하지 않는다.

## 전체 그림

휴대폰 브라우저 또는 홈 화면 앱 → 고객 프로젝트의 Cloud Run 입구 → 사설 VM의 TLS 프록시 → VM 안의 127.0.0.1에서 듣는 momso server 순서다. 입구는 로그인된 사용자만 API에 들이고 화면과 스트림을 전달한다. VM이 꺼져 있으면 입구가 깨우는 구성이다. 고객마다 별도의 `run.app` 입구 주소가 있고 시작 화면의 내 몸소 찾기로 찾는다. 소개 사이트와 별개로 시작·공통 로그인은 `https://anywhere.momso.yoga`에 둔다. [구조와 준비](momso-anywhere-onboarding-s26.md), [PWA](momso-anywhere-pwa-entry-20261121.md).

## 처음 설치

휴대폰 시작 화면은 같은 출처 `/start/`, 공통 로그인은 `/`에 둔다. 시험할 때는 별도 임시 `run.app` 출처를 쓸 수 있다. 프로젝트와 결제 계정을 고른 뒤 설치 단계를 이어가며, 완료 화면에서 사용자가 입구를 연다. 시작 페이지 묶음에는 서명된 목록 URL·공개키·로그인 출처가 필요하다. 목록 서명과 묶음 지문이 맞지 않으면 설치 전에 중단한다. [시작 화면 구성과 단계](momso-anywhere-start-s64.md), [인증과 재시도 계약](momso-anywhere-start-s65.md), [서명 확인](momso-anywhere-signed-install-s73.md).

PC 설치는 `scripts/momso_server_install.py anywhere`를 사용하며 계정·프로젝트·설치 상태 파일을 명시한다. 서버·화면과 서명된 목록의 지문을 검증하고 기존 설치 기록이 있으면 그 설치를 갱신한다. 준비와 명령의 상세 인자는 [설치 안내](momso-anywhere-onboarding-s26.md)와 [서명 및 기존 VM 갱신](momso-release-signing-s76.md)을 따른다. 서로 다른 설치의 상태 파일을 재사용하지 않는다.

## 로그인

입구에서 공통 로그인 페이지와 Google을 거쳐 전체 화면으로 돌아온다. 입구는 state·challenge 쿠키·nonce, Google 서명·대상 및 주인 계정을 확인한다. 토큰 fragment는 각 페이지에서 즉시 주소에서 지운다. 세션은 30일이며, 기기·악성 확장이나 정적 파일 공급망까지 보호한다는 뜻은 아니다. referrer가 있으면 출처를 대조하고 없으면 허용한다. [로그인 검증과 한계](momso-anywhere-s42-login-upgrade.md).

시작 화면의 Google 접근 토큰은 페이지 메모리에만 두고 만료 전 목록·설치·찾기·지우기에 재사용한다. 새로 고치거나 만료되면 다시 인증한다. 공식 문서가 implicit 방식의 보안상 한계를 경고하므로 실제 휴대폰 검증도 필요하다. [시작 인증](momso-anywhere-start-s65.md).

## 올리기

설치와 업데이트는 Ed25519로 서명된 같은 형식의 목록을 확인한다. 목록은 서버·화면 묶음의 SHA-256과 `@sha256` 입구 이미지 지문을 묶는다. 입구는 준비된 revision으로 전환하고 실패하면 이전 트래픽 복구를 시도한다. 설치 중 서버·화면 갱신 실패에도 이전 판 복구를 시도한다. 지문만으로는 서명 검증이 아니다. [목록](momso-anywhere-signed-install-s73.md), [입구 이미지](momso-anywhere-gateway-images-s72.md), [업데이트 계약](server-update-s38.md).

개발과 운영은 서로 다른 공개키와 서명된 채널을 사용한다. 운영 공개키가 고정되지 않으면 운영 묶음은 실패한다. 운영 개인키는 개발자만 보관한다. 개발용 키 생성·목록 서명·기존 VM 올리기 명령과 키 교체 제한은 [S76](momso-release-signing-s76.md)에 있다. 실제 운영 공개키와 서명된 운영 목록은 아직 마련되지 않았다.

## 쉬는 VM 끄기·깨우기

VM 유휴 종료와 입구의 깨우기는 설치·서버 계약을 함께 따른다. VM이 꺼져도 디스크, Cloud Run 등 별도 자원에서 비용이 생길 수 있어 미사용 비용 0원은 보장하지 않는다. 종료 직전 백업을 기다리는 완전한 연결은 아래 백업 상태를 따른다. [구조](momso-anywhere-onboarding-s26.md), [백업 진행 기록](momso-anywhere-backup-s30.md).

## 백업·복원

**VM 자료의 자동 백업은 아직 설치 흐름에 연결되지 않았다.** VM 디스크가 사라져도 복원된다고 안내하면 안 된다. 설계는 고객 프로젝트의 비공개 버킷에 일곱 고정 칸, SQLite 온라인 사본, AES-256-GCM과 고객 프로젝트 KMS의 봉투 암호화를 사용하고, 내용이 같으면 올리지 않는다. 기존 자료는 덮어쓰지 않고 별도 복구 사본으로 둔다. KMS 키가 영구 삭제되거나 프로젝트에 접근하지 못하면 복호화할 수 없다. 서로 다른 DB와 로그인 보관소의 공통 시점은 보장하지 않는다. 버킷·KMS 준비, 주기 실행·종료 전 백업 및 서버 시작 전 복원은 아직 연결·검증해야 한다. [상태와 나머지](momso-anywhere-backup-s30.md).

## 지우기

휴대폰 설치는 `destroyFromGesture` 또는 `scripts/momso_anywhere_destroy_cli.mjs`를 사용한다. 설치 ID와 소유 표식을 확인하며 다른 설치나 기존 프로젝트를 지우지 않는다. VM과 자동 삭제 디스크 및 보관함 열쇠도 삭제하므로 필요한 자료가 있으면 실행하지 않는다. 별도 백업 버킷은 지우지 않는다. Cloud Run 주소 회수 지연 등으로 네트워크가 남으면 같은 프로젝트·설치 ID로 나중에 다시 실행한다. [삭제 명령과 한계](momso-anywhere-start-s65.md).

## 우리 쪽에 한 번 필요한 것

- 시작·로그인 정적 파일을 올릴 출처와 OAuth 웹 클라이언트를 준비한다. 승인된 JavaScript 출처는 `https://anywhere.momso.yoga`, redirect URI는 `https://anywhere.momso.yoga/`와 `https://anywhere.momso.yoga/start/`다. 시험 출처도 정확히 등록한다. Google 설정·시험 사용자·필요 권한의 상세는 [S64](momso-anywhere-start-s64.md)와 [S65](momso-anywhere-start-s65.md)를 따른다.
- 서명된 목록과 검증된 서버·화면 묶음을 제공할 HTTPS 위치, 지문으로 고정한 입구 이미지 저장소를 준비한다. 공개 이미지 저장소 여부는 아직 결정되지 않았다. 비공개 교차 프로젝트 이미지는 Cloud Run 서비스 에이전트와 배포자의 읽기 권한이 필요하다. [이미지 권한](momso-anywhere-gateway-images-s72.md).
- 개발자가 운영 서명 개인키를 관리하고 검수한 공개키를 배포 구성에 고정한다. 키가 고정된 설치기·페이지 자체의 배포 권한도 보호해야 한다. 개발키는 운영과 분리한다. [서명 절차](momso-release-signing-s76.md).

## 아직 실제로 확인할 것

- S68은 가짜 Google·로컬 입구·시험 산출물을 사용한다. 실제 IAM 전파, Cloud Run 이미지 배포·복구, 고객 VM 갱신 및 휴대폰 조작을 대신하지 않는다. [시험 범위](momso-anywhere-integrated-test-s68.md).
- 본부는 이전 실설치에서 Google 로그인·세션 유지와 입구 SSE를 확인했고, S43 갱신 후 주소 직접 열기와 로그인도 확인했다고 보고했다. 이 문서 작성 중 새 실서비스 시험을 한 것은 아니다. 새 서명 목록을 통한 실제 설치·기존 VM 갱신, iPhone 홈 화면 인증과 브라우저별 Ed25519 지원은 별도 확인이 필요하다.
- 자동 백업·복원과 복구 사본 선택 화면은 미완성이다. 공개키·공개 목록 및 이미지 게시 위치도 준비가 필요하다.

## 원문 대조와 옛 경로

옮긴 결정·조건의 대조 기록은 아래와 같다. 원문의 모든 세부 사항을 이 안내서로 옮긴 것은 아니며, 빠진 상세 숫자·명령·보안 조건은 연결된 원문을 정본으로 한다. 뜻이 바뀐 것으로 확인된 항목은 없다. 옛 문서의 당시 상태는 최신 확인으로 바꾸지 않았고, 이후 본부가 보고한 실제 확인은 별도로 표시했다.

| 안내서의 항목 | 대조한 원문 | 결과 |
| --- | --- | --- |
| 출처·고객 입구·VM 경로 | S26, PWA | 일치; 실제 기기 확인은 별도 |
| 프로젝트·결제 선택과 서명 전 설치 중단 | S64, S73 | 일치; 화면별 반환값은 원문 참조 |
| 전체 화면 로그인·30일 세션·referrer | S42 | 일치; 실제 기기와 공급망 한계 보존 |
| 토큰의 메모리 보관·재인증 | S65 | 일치; implicit 보안 경고 보존 |
| 이미지 지문·서명·개발/운영 분리 | S72, S73, S76 | 일치; 실제 운영 키 미준비 보존 |
| 유휴 비용과 백업 미완료 | S26, S30 | 일치; 비용 0원·자동 복원으로 단정하지 않음 |
| 일곱 칸·암호화·복구 충돌 | S30 | 일치; 설계와 구현 상태 구별 |
| 소유권 검사·삭제·지연 재시도 | S65 | 일치; 보관함 열쇠 삭제 경고 보존 |
| OAuth 출처·redirect와 서명 준비 | S64, S65, S76 | 일치; 시험 출처와 운영 출처 구별 |
| 시험 범위와 실제 확인 | S68 및 본부 후속 보고 | 가짜 시험과 실제 확인을 따로 기재 |

Cloudflare 기반 `mobile` 및 IAP 깨우기의 소스 배포는 현재 `anywhere` 기본 경로가 아니지만 별도 명령과 기존 자원 제거에서 실제로 호출된다. 동등한 이전·제거 경로를 확인하지 못해 삭제하지 않았다. `retryFromGesture`도 인증 만료 복귀 및 호환 경로에서 호출된다. 이번 조사에서 안전하게 삭제할 수 있는 옛 코드는 확인하지 못했다. [이전 연결 기록](momso-mobile-connection-s19.md).
