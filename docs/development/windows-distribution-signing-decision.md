# momso Windows 배포·코드 서명 결정 기록

> **2026-11-24 새 결정:** 개발자: “인증서는 돈 안낼래.” Windows 코드 서명 인증서는 구매하지 않고 인증서 서명 없는 설치 파일을 배포하며 SmartScreen 경고를 받아들인다. Tauri 자동 업데이트 서명은 유지한다. 이 새 결정이 아래 2026-07-12 기록의 결정 보류, 내부 전용, 인증서 명의·비용 확인을 선행하는 조건을 대체한다. 아래는 당시 기록이다.

> 기준일: 2026-07-12
> 상태: 결정 보류, 서명 기능 비활성
> 현재 배포물: NSIS current-user, 사설 GitHub Actions 내부 테스트본

## 1. 지금의 결정

현재 설치본은 **팀 내부 실행 검증에만 쓰는 서명되지 않은 파일**로 유지한다. 외부 테스트 대상, 배포 채널,
법인 명의와 비용, 서명 키 책임자가 정해지기 전에는 인증서를 구매하거나 CI에 시크릿을 넣지 않는다.

빌드가 성공했다는 사실과 외부에 안전하게 배포할 수 있다는 판단은 다르다. 지금 CI는 설치 가능 여부,
SHA-256, 원본 커밋을 증명하지만 Windows 평판 경고를 없애거나 배포 주체의 신원을 증명하지는 않는다.

## 2. 헷갈리기 쉬운 두 서명

| 구분 | 무엇을 증명하는가 | 현재 상태 |
|---|---|---|
| Windows 코드 서명 | EXE 또는 패키지가 배포 주체에게서 왔고 변조되지 않았는지 | 비활성 |
| Tauri 업데이터 서명 | 앱이 내려받은 업데이트 파일이 momso가 만든 파일인지 | 업데이터 자체 비활성 |

두 서명은 목적과 키가 다르다. Windows 인증서를 샀다고 Tauri 자동 업데이트가 바로 켜지는 것도 아니고,
Tauri 업데이트 키를 만들었다고 Windows 설치 경고가 해결되는 것도 아니다.

## 3. 검토할 배포 선택지

| 선택지 | 맞는 상황 | 결정 전에 확인할 것 |
|---|---|---|
| 현재처럼 unsigned NSIS | 소수 내부 인원이 출처와 체크섬을 직접 확인 | 외부 공개 금지, 설치 경고 수용 |
| Microsoft Store 중심 | Store 심사와 배포 체계를 채택하고 패키지 전략도 함께 바꿀 때 | 현재 NSIS와 별개로 MSIX/Store 제출 흐름 검증 |
| Microsoft Artifact Signing | 지원 지역·조직 자격을 충족하고 클라우드 관리형 서명을 원할 때 | 신청 자격, 비용, SignTool/Tauri CI 연결, 장애 시 수동 배포 |
| 상용 코드 서명 인증서 | 현재 NSIS를 직접 서명하고 키 보관 책임을 질 수 있을 때 | 발급 주체, 비용, 키 보호, 갱신·타임스탬프·폐기 절차 |
| 자체 서명 인증서 | 통제된 사내 PC에 신뢰 루트를 직접 배포할 때 | 일반 외부 사용자는 신뢰하지 않으므로 공개 알파에 부적합 |

Microsoft의 현재 선택지와 자격 조건은 실제 결정일에 다시 확인한다. 서비스 이름, 지원 지역, 가격과
신원 확인 조건은 바뀔 수 있다.

## 4. 사람이 답해야 하는 질문

아래 질문에 모두 답하기 전에는 서명과 자동 업데이트를 켜지 않는다.

1. 첫 외부 테스트 사용자는 몇 명이며, 우리가 직접 연락할 수 있는가?
2. 다운로드는 GitHub 사설 산출물, 별도 HTTPS 페이지, Microsoft Store 중 어디에서 제공하는가?
3. 계약과 인증서의 명의는 누구 또는 어느 법인인가?
4. 초기 비용과 매년 갱신 비용을 누가 승인하는가?
5. 서명 키와 Tauri 업데이트 키의 책임자·백업 위치·복구 절차는 무엇인가?
6. 잘못된 버전을 배포했을 때 중단·롤백·사용자 공지 절차는 무엇인가?
7. 설치본이 로컬 DB를 변경할 때 마이그레이션 전 백업과 복구 리허설이 끝났는가?

## 5. 활성화할 때의 최소 게이트

1. 선택지와 책임자를 이 문서에 `채택`으로 기록한다.
2. 테스트용과 운영용 키를 구분하고 저장소 파일에 넣지 않는다.
3. CI 로그와 build manifest에 인증서 원문이나 시크릿을 남기지 않는다.
4. 서명 뒤의 최종 EXE를 다시 SHA-256 계산하고 서명 검증 명령을 통과시킨다.
5. 깨끗한 Windows 테스트 환경에서 설치·실행·업데이트 또는 제거를 확인한다.
6. 실패 시 unsigned 파일을 외부에 대신 공개하지 않고 배포를 중단한다.
