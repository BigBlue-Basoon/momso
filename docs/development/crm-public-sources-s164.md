# 세 운영 서비스의 공개 자료와 CRM 칸 초안

확인일: **2026-11-25**. 공개된 공식 도움말·기능 소개만 읽었다. 가입, 로그인, 약관 동의, 체험 신청과 문의 제출은 하지 않았다. 실제 관리자 계정과 수련생 정보는 보지 않았다. 아래 `확인 못 함`은 공개 자료에서 찾지 못했다는 뜻이지 기능이 없다는 뜻이 아니다. 바디코디의 **강사앱**·**회원앱** 안내는 PC 관리자 화면과 구분한다. 도움말에는 개선 예정 화면이 섞여 있을 수 있으므로 날짜와 실제 화면을 다시 확인한다.

## 현재 몸소 초안과의 대조

기준은 통합 가지 `feat/desktop-panel-browser`의 `0cc116a3f`에서 읽은 `apps/alpha/desktop/src-tauri/src/class_student_core.rs`와 `docs/development/desktop-class-student-s9-contract.md`다. 실제 화면의 완전한 목록이 아니므로 `초안에만 있음`은 **이번 공개 자료에서 대응 항목을 확인하지 못함**을 뜻한다. 열거되지 않은 필드를 자동 추가하거나 DB를 바꾸지 않는다.

## 바디코디 스킬 안내서 초안

이 절은 **검토용 초안**이다. 내장 스킬에 등록하지 않았다. 스킬은 안내서이며 브라우저가 갈 수 있는 사이트를 제한하지 않는다.

1. **시작·로그인:** `https://crm.bodycodi.com`을 열어 현재 화면을 읽는다. 로그인이나 인증번호가 필요하면 사용자에게 직접 하도록 요청한다. 비밀번호·인증번호를 AI가 입력하지 않는다. 로그인 뒤 다른 호스트나 메뉴는 확인 못 함.
2. **예약 보기:** 사용자가 원하는 날짜·대상만 확인한다. 공개 권한 안내의 `스케줄러 > 개인레슨스케줄` 또는 `스케줄러 > 그룹수업스케줄`을 화면에서 찾아 해당 일정의 상세를 연다. 실제 예약 명단의 PC 화면과 정렬·페이지 넘김은 **로그인해서 확인할 것**. 강사앱 상세에서 수업 상태·회원·대기 등을 볼 수 있다는 사실을 PC의 확인된 단추 순서로 오인하지 않는다. [권한 안내](https://crm-guide.bodycodi.com/03d9bd74-7520-444f-bd70-8f84a4103563), [강사앱 상세](https://crm-guide.bodycodi.com/2bfe5018-e52c-41c4-b348-855db82cf53e), 2026-11-25.
3. **예약 바꾸기:** 개인레슨의 공개 경로는 `스케줄러 > 개인레슨스케줄 > 예약내역수정 > 시간 수정`. 대상 회원·수업·날짜와 새 시간을 먼저 확인하고, 바뀔 내용과 알림·취소 조건을 사용자에게 말한 뒤 답을 받는다. 실제 저장·확인 단계는 **로그인해서 확인할 것**. 그룹수업 전체 취소를 개인의 예약 변경으로 대신하지 않는다. [권한 안내](https://crm-guide.bodycodi.com/03d9bd74-7520-444f-bd70-8f84a4103563), 2026-11-25.
4. **출석 확인:** 공개 자료에서 PC `스케줄러` 출석 처리를 언급한다. 먼저 원하는 수업의 상세에서 상태를 읽되, PC의 실제 명단 위치와 표시값은 **로그인해서 확인할 것**. 출석 변경은 읽기와 다르므로 사용자에게 결과를 설명하고 답을 받은 뒤에만 한다. [체크인](https://crm-guide.bodycodi.com/413f3526-6321-45cb-86e8-363be4a649a7), 2026-11-25.
5. **수련생 찾기:** `고객관리 > 회원검색` 또는 공개 권한 안내의 `회원검색 > 회원선택`을 화면에서 찾아 요청받은 회원을 확인한다. 이름이 같으면 다른 정보로 구별하되 필요한 정보만 읽는다. 검색 결과 열·상세 화면·마스킹과 페이지 수는 **로그인해서 확인할 것**. [권한 안내](https://crm-guide.bodycodi.com/03d9bd74-7520-444f-bd70-8f84a4103563), 2026-11-25.
6. **표 읽기:** 화면의 열 이름·날짜·시간대·상태·페이지 수를 먼저 확인하고, 물어본 범위만 정리한다. 안 보이는 열을 추측하거나 일부 목록을 전체로 말하지 않는다. 등록·삭제·결제·취소·발송처럼 되돌리기 어려운 일은 하기 전에 무엇을 하려는지 채팅으로 말하고 사용자의 답을 받는다.

사이트를 누르고 입력하는 기술적 승인은 채팅방·사이트 단위로 기억될 수 있다. 그 승인이 앞서 주어졌다면 저장 직전에 새 카드가 반드시 뜨는 것은 아니다. 따라서 안내서의 ‘무엇을 할지 설명하고 답 받기’는 사이트 접근 승인과 별도로 지켜야 하며, 자동 승인 카드가 매 저장을 막아 준다고 가정하지 않는다.

## 로그인해서 확인할 것

1. 그가 직접 바디코디에 로그인한다. 로그인 뒤 주소와 화면의 메뉴 이름·권한 차이를 확인한다. 비밀번호와 인증번호를 기록하지 않는다.
2. 오늘 날짜의 개인레슨·그룹수업을 차례로 열어 이름, 시간대, 강사, 정원, 장소, 수업 정의와 일정의 번호 및 페이지 수를 확인한다.
3. 한 수업의 예약 명단·대기·좌석·출석/결석 표시와 예약자 상세를 읽는다. 실제 정보는 필요한 범위만 다루고 이 문서에는 칸 이름만 남긴다.
4. 회원 검색에서 이름·회원번호·연락처의 구별법, 마스킹, 이용권·상담·메모와 강사 연결을 본다.
5. 예약 변경·개별 취소와 수업 전체 취소를 구분해, 마감·회수 차감·알림·확인창이 어디에 보이는지 확인한다. 실제 변경은 그가 요청하고 승인한 경우에만 한다.
6. 엑셀 다운로드의 권한·열·암호·마스킹·CSV 가능 여부를 확인한다. 실제 파일을 받는 것은 별도 지시를 따른다.
7. 온스튜디오와 네이버도 같은 순서로 화면·필드·예약 정책을 대조하고, 채널별 번호와 동기화 관계를 확인한다.
