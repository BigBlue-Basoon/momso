# 데스크톱 새 PC 복원 점검

이 문서는 S152 당시의 점검 기록이다. 자동 DB 백업과 Git·DB 묶음의 후속 구현 및 검증 상태는 [S160 진행 기록](desktop-paired-backup-s160.md)을 확인한다. 아래에서 별도 백업과 시점 불일치에 관해 설명한 내용은 S152 당시의 동작이다.

GitHub 연결 화면의 `remoteConnect`는 `archive_remote_connect`를 부른다. 기존 Git 이력이 없는 새 몸소 폴더에서 연결하면 `connect_impl`이 첫 받기를 수행하고, 채팅 사본·문서 등을 반영한다. 연결 상태와 첫 받기 충돌은 설정 화면에서 확인한다. 원자료 저장소는 별도다. 설정의 연결은 `object_store_connect`이고, 연결만으로는 복원이 끝나지 않는다. 화면의 되살리기 단추는 `app_state_restore` 다음 `object_store_restore`를 호출한다. 복구 키는 설정의 `import_backup_recovery_key`로 새 PC에 넣어야 한다.

자동 원자료 업로드(`object_store_auto_upload` → `backup_with_mode`)는 원자료 파일을 올리지만 앱 DB의 `app_state_backup`을 호출하지 않는다. 설정의 `storeBackup`은 두 명령을 차례로 부른다. 따라서 원자료 자동 업로드가 켜져 있다는 사실만으로 최신 앱 DB가 별도 백업됐다고 보장할 수 없다. 새 PC에서 복구 키 입력과 되살리기를 언제 안내할지, 앱 DB의 자동 백업을 어떤 때 실행할지는 화면·제품 흐름에서 정해야 한다.

기존 코드는 원자료의 같은 경로에 다른 파일이 있으면 `local_conflict`로 멈추고, 수업·학생 DB에 내용이 있으면 새 사본을 별도 보존한다. 앱 DB는 교체 전에 안전 사본을 만들지만 다른 로컬 대화는 일반 목록에서 사라질 수 있었다. 이제 앱 DB 복원은 현재 PC의 대화·첨부·프로젝트·원자료·기록 등 사용자 자료가 백업에 없거나 다르면 `local_data_conflict`로 멈춘다. 빈 초기 채팅은 허용한다. 진행 중인 AI 턴이 있으면 `restore_busy`를 반환한다. 화면은 이 두 상태의 안내를 정해야 한다. 검사는 같지 않은 자료를 자동 병합하지 않는다.

현재 저장된 로그인은 Windows 자격 증명 관리자에만 있고 백업에 포함되지 않는다. 새 PC에서는 사이트 아이디와 비밀번호를 다시 입력해야 한다. 이 문서의 채팅·원자료 왕복 시험은 저장된 로그인 복원을 증명하지 않는다. AI 공급자와 GitHub·원자료 저장소 연결에 필요한 자격 증명도 새 PC에서 다시 연결하거나 입력해야 한다. 원자료와 앱 DB를 복원하려면 기존 백업의 복구 키도 직접 입력해야 한다. 화면 담당자는 이런 재입력과 복구 키 필요 사실을 사용자에게 안내하는 위치를 정한다.

시험은 가짜 원격과 시험용 자격 증명만 사용한다. 실제 계정·버킷의 복원이나 실제 새 PC 화면은 확인하지 않는다.

## 점검 결과와 화면 인계

- `sqlite_snapshot_round_trip_preserves_current_state_before_restore`: 로컬 bare Git과 로컬 폴더를 사용하는 가짜 객체 서버에서 같은 시점의 문서·채팅·첨부를 새 프로필로 되살리고 첨부 SHA-256을 대조했다. 복구 키 없음, 다른 키, 손상된 암호문도 검사했다. 이 시험은 실제 Tauri 화면 호출 전체가 아니라 그 뒤쪽의 복원 함수들을 호출한다.
- Git 사본과 앱 DB 백업의 시점이 달라 채팅방의 고정·보관 상태가 서로 다르면 `local_data_conflict`로 멈춘다. 새 PC에 받은 Git 사본이 오래된 경우에도 자동으로 어느 쪽이 최신인지 판단해 합치지는 않는다. 원본을 잃지 않기 위한 제한이므로 화면에서 충돌 안내와 다음 선택지를 정해야 한다.
- 새 PC에 있던 대화·첨부 등 다른 자료는 덮어쓰지 않고 `local_data_conflict`를 반환한다. 실행 중인 AI 턴이 있으면 `restore_busy`다. 화면에서는 두 값을 구분해 안내해야 한다.
- 새 PC에서는 GitHub와 원자료 저장소를 다시 연결하고, 기존 복구 키를 입력한 뒤 되살리기를 눌러야 한다. 저장된 로그인과 AI 공급자 자격 증명은 다시 입력한다. 원자료 자동 업로드와 앱 DB 백업이 별개라는 점도 화면에서 설명할 필요가 있다.
