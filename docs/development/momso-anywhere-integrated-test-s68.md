# momso anywhere 설치 시험 S68

검증 기록: 2026-11-22 개발용 리눅스 VM, 코드 `d783095cf`, 시험 산출물 `03acec76c`. 연결 흐름을 포함해 41개 통과, 0개 실패. 아래 차이 때문에 실제 Google·휴대폰 확인을 대신하지 않는다.

## 한 명령으로 실행

리눅스에서 `node`, Python 3, `bubblewrap`, `openssl`, `age-keygen`, `git`과 시험용 서버·화면 산출물이 필요하다. 산출물 폴더에는 `momso-server`, `web.tar.gz`, `SHA256SUMS`가 있어야 한다. 실제 계정·실제 스토리지는 쓰지 않는다.

```sh
MOMSO_S68_ARTIFACT_DIR=/path/to/test-artifacts sh scripts/test_momso_anywhere_s68.sh
```

서버와 화면의 SHA-256을 대조한다. 로컬 포트 8765가 이미 사용 중이면 실제 서버 구간을 건너뛰므로, 그런 실행은 통과로 간주하지 않는다. 오류를 고치고 다시 실행한다.

## 확인하는 것

- 가짜 Google REST에서 새 프로젝트와 기존 프로젝트 각각 설치를 중단 후 재개하고, 방금 만든 같은 설치의 자원만 제거한다. 다른 프로젝트는 지우지 않는다.
- 가짜 새 설치가 준비된 뒤 생성된 VM 시작 스크립트 전체를 bubblewrap의 일회용 파일 시스템과 분리된 네트워크에서 실행한다. 검증한 서버·화면 묶음, 프록시 파일과 가짜 코덱스 자리를 설치하고 해시·생성된 서비스 파일을 확인한다. 실제 VM의 `/opt`, `/etc`, 자료는 건드리지 않는다.
- 그 시작 스크립트가 설치한 서버 실행 파일·화면과 실제 TLS 프록시·입구 코드를 로컬로 띄운다. 시험용 보관소 열쇠를 만들고, 시험용 신원으로 세션을 만든 다음 화면·`/health`·`/providers`·`/chats`·`/documents`·`/saved-logins`를 요청한다. 가짜 코덱스가 한 턴을 답한다.
- 설치기의 `upgrade_anywhere`에 새 해시의 시험 묶음과 지문 고정 입구 이미지를 넘긴다. 가짜 Cloud Run이 S48 어댑터의 무트래픽 revision 준비·트래픽 전환을 받고, 로컬 공급자가 서버를 다시 띄운 뒤 같은 입구에서 기존 대화와 새 화면 파일을 확인한다. 휴대폰 REST의 이전 트래픽 보존·복구와 소유권 불일치, 지연된 네트워크 제거의 재시도도 시험한다.

## 실제와 다른 점

가짜 Google REST가 새 설치를 마친 뒤 같은 시험 안에서 격리 시작 스크립트와 로컬 서버를 차례로 실행하고, 그 뒤 같은 설치 ID를 가짜 REST에서 제거한다. 격리 스크립트는 같은 생성기의 코드이지만 가짜 REST에 전달한 값이 아닌 별도 시험 묶음 주소와 해시로 실행한다. 시험은 Google의 IAM 전파·Cloud Run 배포·고객 VM SSH 전송을 검증하지 않는다.

시작 스크립트에서는 Google 메타데이터·비밀값·health 응답과 systemd 실행을 가짜로 제공한다. 실제 systemd 서비스 시작, 패키지 설치와 코덱스 공식 바이너리 내려받기는 확인하지 않는다. git 설치 순서는 별도 가짜 시험이며, 시험 호스트에 이미 설치된 git으로 서버를 실행한다.

가짜 로그인 검증기는 서명 검증 대신 시험 클레임을 반환한다. 입구의 state·nonce·소유자와 쿠키, 프록시 TLS 지문은 실제 코드를 사용하지만 실제 Google 로그인은 확인하지 않는다. 화면은 실제 정적 묶음이지만 휴대폰 조작은 하지 않는다.

올리기는 로컬 공급자에 연결한 실제 `upgrade_anywhere` 함수로 검증한다. 서버 묶음은 같은 실행 파일에 시험 표식을 덧붙여 해시만 달라진 것이므로 서로 다른 실제 서버 버전 간 호환성 시험이 아니다. 클라우드 배포와 실제 복구는 별도 시험이 필요하다. 제거 검사는 가짜 Google 자원에만 적용되며 로컬 임시 자료는 시험 종료 시 지운다.
