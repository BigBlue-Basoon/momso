# S117c 휴대폰 시작 경로 연습

실행은 본부가 한다. 이 명령은 선택한 **기존 프로젝트 안에 새 시험 설치**를 만들고, 입구 단계 직전에 일부러 멈췄다가 같은 설치 번호로 다시 이어서, 확인 후 휴대폰 삭제 함수를 호출한다. 보호 설치 번호와 프로젝트 삭제는 별도로 막는다. 로그인 토큰은 지정한 계정의 `gcloud`에서 메모리로만 받아 API에 쓰며 화면이나 상태 파일에 남기지 않는다.

```powershell
node scripts/momso_anywhere_rehearsal_s117c.mjs --account "<계정>" --project "<기존 프로젝트>" --manifest-url "<서명 목록 주소>" --public-key "<공개키 파일>" --channel production --google-client-id "<Google 로그인 앱 ID>" --login-origin "<로그인 출처>"
```

시험 번호는 변경 전에 출력한다. 서명 목록·공개키와 로그인 출처는 실제 사용할 값이어야 한다. `project`, `billing`, `services`, `privateNetwork`, `server`, `gateway`, `gatewayReady`의 진행과 일부러 발생시킨 `gateway` 실패, 이어진 결과가 표시된다. 보호 번호와 같은 앞 12자리는 사용하지 않는다. 오류 원문이나 토큰은 출력하지 않는다. 설치가 시작된 뒤 오류가 나도 삭제와 잔여 조회를 시도한다.

입구에서 실제 트래픽을 받는 판의 이미지 지문을 서명 목록과 대조하고 로그인 전 공개 경로의 HTTPS 응답을 확인한다. 휴대폰 설치 VM은 SSH를 기본적으로 막으므로, 네 서비스와 인증된 `/update/status` 확인을 위해 **그 새 시험 VM의 전용 네트워크에만** IAP의 주소 범위에서 SSH를 허용하는 임시 규칙을 만들고, 소유 표식을 확인해 즉시 삭제한다. 임시 SSH 키도 지운다. 첫 SSH 접속은 IAP 통로를 쓰며 호스트 키를 미리 알고 있지 않다. 이는 진단을 위한 추가 접근이지 휴대폰 기본 설치 동작은 아니다. 규칙을 지웠다는 확인이 없으면 두 VM 확인은 미확인으로 두고 `diagnosticRule`에 남은 규칙 이름을 표시한다.

백업 버킷과 키는 시험 번호·소유 표식을 확인한 경우에만 정리한다. 파기 예약된 키 버전은 실제 파기 시각까지 과금될 수 있으며, 가능한 경우 그 시각을 표시한다. 잔여 조회에서 404는 권한 때문에 숨겨졌을 수 있으므로 `없음`으로 단정하지 않는다. IAM·보호된 삭제본 등 확인하지 못한 것은 `미확인`이다. 조회가 미완이면 종료 코드는 0이 아니다. 강제 종료나 전원 차단은 정리 함수를 건너뛸 수 있으므로, 이때는 미리 출력된 설치 번호와 `momso-<앞 12자리>-s117c-iap` 규칙을 확인해야 한다.

이 연습은 Node의 HTTP 요청이다. 실제 휴대폰 브라우저의 CORS, 화면 이동·기기별 저장소와 터치 동작은 확인하지 못한다. 브라우저의 인증 복귀 화면은 대역이고, 그 대역이 전달하는 범위 목록은 실제 브라우저가 받은 범위의 증거가 아니다. `gcloud` 토큰의 권한과 브라우저 토큰의 권한도 다를 수 있다. Google의 실제 API는 전달된 토큰의 권한을 별도로 검사한다. 이 차이와 실제 Google 로그인은 휴대폰에서 따로 확인한다.
