# 서버의 실제 브라우저 시험 (S144)

## 환경과 범위

지정된 개발 VM을 직접 확인한 결과 운영체제는 **Ubuntu 24.04.5 LTS**였다. 요청된 Debian 12와 다르므로 아래 결과는 Debian 12에서의 검증 결과가 아니다. Google Chrome 158.0.8127.36을 사용했다. 실제 고객 계정이나 개인정보는 쓰지 않았다. 브라우저는 제품의 `HeadlessBrowser::launch`와 동일한 headless 실행·디버깅 파이프 및 채팅별 프로필을 사용했다.

2026-11-25 검증: 서버 코드 `68cc36ba0`, 네트워크 화면 스냅샷 `82ec80c`에서 실제 브라우저 시험 **15개 통과, 0개 실패**. 서버와 브라우저 모듈의 fmt·clippy도 통과했다. 최초 휴대폰 화면 시험은 미리보기 모드와 가짜 AI의 주소 파싱 오류 때문에 실패했으며, 네트워크 모드와 테스트 대본을 바로잡은 뒤 세 화면 흐름이 통과했다.

기존 설치기는 브라우저를 설치하지 않았으므로, 브라우저가 없을 때 Chromium을 설치하고 서버가 설치된 실행 파일을 찾도록 보완했다. Debian 12의 Chromium 꾸러미는 [Debian 공식 패키지](https://packages.debian.org/bookworm/chromium)에 있다. 이 설치 경로와 Debian의 샌드박스는 실제 Debian VM에서 아직 시험하지 않았다.

## 개발 VM에서 다시 실행

저장소 루트에서 `bash apps/alpha/server-browser/scripts/s144-real-browser-tests.sh`를 실행한다. Chrome 또는 Chromium, Rust, ffmpeg, Node.js가 필요하다. 휴대폰 화면 시험에는 네트워크 모드로 빌드한 화면의 `dist`와 Playwright가 필요하다. 각각 `MOMSO_S47_SCREEN_DIR`, `MOMSO_S47_PLAYWRIGHT`로 지정한다. 기본값은 `~/momso-build/s144-screen/apps/alpha/desktop/dist`와 `~/momso-build/s144-screen/node_modules/playwright`다. 화면은 예를 들어 해당 스냅샷에서 `npm ci` 후 `VITE_MOMSO_NETWORK=1 npm run desktop:ui:build`로 만들고 Playwright를 설치한다. 준비물이 없으면 해당 시험은 통과로 처리되지 않는다.

## 확인한 것과 한계

- 서버 브라우저 모듈의 실제 브라우저 시험 5개: 채팅방별 프로필, 쿠키 유지, 승인·거절, 로그인 채우기, 프레임·새 창, 지연 화면 및 가짜 사이트의 수업 등록·CRM 읽기.
- 가짜 Claude·Gemini 공급자가 서버 브라우저 도구를 호출하여 승인 뒤 가짜 사이트에 등록하는 시험 1개.
- 서버의 실제 브라우저 제외 시험 9개: 가짜 Codex와 두 공급자의 승인 왕복, 공개 페이지 열기·읽기·누르기, 사람 입력·저장 로그인과 재연결, 동영상 미리보기. 휴대폰 크기 화면에서도 사람 확인 안내, 일회용 번호 입력·전달, 저장된 로그인 선택·전달을 가짜 사이트로 확인했다.
- 현재 서버 브라우저 도구에는 웹사이트 파일 업로드·다운로드 전용 명령이 없다. 해당 기능의 브라우저 왕복 시험은 하지 않았다.

## 자원 측정

VM 전체 메모리 15,985 MiB, 시험 전 가용 메모리 15,014 MiB, 디스크 48 GB 중 사용 가능 40 GB였다. 실제 브라우저를 채팅방마다 하나씩 띄운 시험에서 한 방은 프로세스 15개 RSS 합계 1,256,448 KiB·967 ms, 세 방은 프로세스 45개 RSS 합계 3,766,148 KiB·2,359 ms였다. 시간은 시험 시작부터의 누적 시간이고 RSS 합계에는 프로세스 간 공유 메모리가 중복될 수 있어 실제 고유 사용량보다 클 수 있다. 이 수치만으로 모든 사용 상황의 적정 VM 크기를 보장할 수 없다.
